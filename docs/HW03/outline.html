  8. hidden_states 的 27 個索引：[0] 是 embedding × √2304，[i] 是第 i−1 個 decoder block 的輸出，[26] 是經過最後 norm 的結果。這一節是第 6、8、9 章的前置知識。

第 5 章　Q4（下）self-BLEU、seed 與可重現性

對應原始碼
hw3.py:188–197 compute_self_bleu；:241–250 印出句子與分數；:506–507 torch.manual_seed。
各節
  1. BLEU 在量什麼：n-gram 重疊、4-gram 等權、沒有 smoothing；只要沒有任何 4-gram 重疊就是 0，所以會出現 nltk 的 0 counts of N-gram overlaps 警告。
  2. self-BLEU：每句當 hypothesis、其他 19 句當 reference，越高代表越不多樣；完全相同的句子 BLEU = 1.0。
  3. hw3.py 跑出來的分數：--q 4 --seed 0 是 0.2029 與 0.5542；--top-k 200 --top-p 0.999 是 0.1343 與 0.0625；k=1、p=0 都是 1.0000。注意 hw3.py 在同一次執行裡先抽 top-k 再抽 top-p，共用同一條亂數流，所以它的 p=0.999（0.0625）和第 4 章 facts 腳本各自 seed 0 起算的 0.1257 不是同一個量。
  4. 換 5 個 seed 看分布：結論穩定（k=2 > k=200、p=0.6 > p=0.999），數值波動大（p=0.6 在 0.43–0.77 之間），所以單次的數字不要當成定值。
  5. 兩組設定抽出一模一樣的句子：top_k=200 與 top_p=0.999, top_k=0 在 5 個 seed 下完全相同；推論是兩者在這個 prompt 上保留的 token 集合幾乎相同，同一條亂數流就抽出同樣的結果（要標明是推論）。

第 7 章　Q6 Attention map：逐步生成時誰在看誰

對應原始碼
hw3.py:301–309 plot_attention；:312–366 q6（HybridCache :324、手寫生成迴圈 :328–358、TODO :339–344、累積矩陣 :346–350、標籤 :365）。
各節
  1. 為什麼不用 generate：要拿每一步的 attention，所以自己寫迴圈；cache_position、attention_mask 每步加一格。
  2. KV cache 與 attention 的形狀：HybridCache 是 Gemma 2 用的 KV cache 類別（模型 generation_config 的 cache_implementation 就是 'hybrid'）；max_cache_len = 20 + 3 − 1 = 22；第 0 步 (1, 8, 3, 22)，之後每步 (1, 8, 1, 22)；還沒寫入的欄被 mask 成 0；累積起來 22 列。
  3. eager 與 soft-capping：attention 權重是 softmax(tanh(score / 50) × 50)，所以要 eager 路徑（回指第 0 章）。
  4. layer 10、head 7 在看什麼：每列注意 <bos> 的比例（第 1 列以後平均 0.373）；▁internet 之後幾個 token 最注意 ▁in、▁specializes。
  5. 對照組：layer 0 head 0 像 previous-token head；layer 25 head 0 每一列都最注意 <bos>（平均 0.763）。
  6. attention sink：各層對 <bos> 的平均注意力 0.53–0.91；<bos> 的 hidden state 範數從第 5 層起約是其他 token 的 10 倍（兩者的關聯要標明是推論）。sliding 與 global 層在這麼短的序列上行為一樣。
