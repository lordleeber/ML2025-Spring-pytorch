ML2025 Spring HW03 教材

Understanding Transformers：用 Gemma-2-2b-it 看懂 LLM 的內部

這本書帶你逐行讀 HW03/hw3.py：它把台大李宏毅老師 ML2025 Spring 第三次作業的官方 Colab 改寫成一支可以在本機跑的腳本。七個題目各自從一個角度打開 Gemma-2-2b-it：輸入格式、tokenizer、取樣、句子表示、注意力、稀疏自編碼器（SAE）。每一章都對應腳本裡真實的函式與行號，每一個數字都來自本機實際跑出來的紀錄。

這本書是什麼

一本「讀 code、看實測、懂每一題在量什麼」的教材，不是解答本。

  • 對象：會寫 Python、用過 PyTorch 的 tensor，聽過 Transformer，但沒有拆開過一個真的 LLM。
  • 主線：每一章讀 hw3.py 的一個題目函式，貼出真的執行輸出，解讀「這行數字證明了什麼」。
  • 副線：原版程式有幾個刻意保留的怪地方（例如 prompt 開頭有兩個 <bos>），每章用「讀 code 不盡信文件」框把它們拆開，並附上修正前後的實測對照。

1　這份作業在做什麼

HW03 的題目叫 Understanding transformers，助教是傅啟恩、李冠儀、許景淯，期限 2025/04/04。作業用 Google 的 Gemma-2-2b-it（約 26 億參數；名稱裡的 -it 是 instruction-tuned，指經過指令微調、會照對話指示回答的版本），在 Colab 上完成七大題的程式，然後到 Gradescope 回答選擇題與填空題。計分方式見投影片（repo 裡的 HW03/hw3.pdf，共 35 頁）p.4 與 p.32：

這本書不提供 Gradescope 的答案

Gradescope 上每一題的選項不在投影片、也不在 Colab 裡，這本書不會編造選項，也不會把任何敘述寫成「標準答案」。投影片 p.34 明訂不得分享答案。所以這本書的定位是：講清楚每一題在量什麼、程式怎麼量，並列出本機實測的數字。Q3 的填空答案不直接寫出，只示範怎麼把它跑出來。你在自己的機器上跑出的數字，可能因為 GPU 與套件版本而有小差異。

論文閱讀（Problem 8–9）不在程式範圍內，這本書只在附錄的延伸閱讀列出三篇論文。

2　原版 Colab vs 本 repo

助教提供的是一本 39 格、沒有輸出的 Colab notebook（HW03/hw3_colab.ipynb，原始連結 colab.research.google.com/drive/1Ku_p27…）。本 repo 把它改寫成一支 521 行的腳本 HW03/hw3.py。改寫的原則寫在腳本開頭的 docstring（hw3.py:1–13）：只改「在本機跑不動或不方便」的地方，其他行為刻意和 Colab 保持一致，讓結果和助教那邊一致：投影片 p.32 說助教會重跑你的程式核對結果，重現不出來的題目以零分計。

2.2　刻意保留沒改的怪地方

docstring 說得很清楚：「Everything else (including quirks like the double <bos> in Q1/Q2) is kept identical to the Colab」。這些怪地方不會讓程式當掉，但會讓某些數字或圖的意思和你直覺以為的不一樣。這本書把它們當成教材：每一條都在對應的章節用「讀 code 不盡信文件」框拆開，並附上本機量到的修正前後對照。

  • Q1、Q2 的 prompt 開頭有兩個 <bos>：<bos> 是標記「序列從這裡開始」的特殊 token，正常只該有一個。chat template（把使用者的問題包成模型訓練時看過的對話格式的那段字串）已經帶一個，tokenizer 又加一個，模型看到的輸入因此和訓練時不同（第 1 章）。
  • Q4 的 top-p 其實同時開著 top-k=50：top-k 是「只從機率最高的 k 個 token 裡抽」，top-p 是「只從累積機率達到 p 的那群 token 裡抽」，作業要比較兩者。但 transformers 的 model.generate 沒指定 top_k 時會用預設值 50，所以「top-p 組」其實兩個規則都開著（第 4 章）。
  • Q5 的句子向量把 padding 也平均進去：六句話長度不同，一起送進模型時短句會補上 <pad> 湊成同樣長度；把每個位置的向量平均成句子向量時，這些補位也被算進去了（第 6 章）。
  • Q6 的 attention heatmap 標籤整排錯位一格（第 7 章）。
  • Q6 的 heatmap 最後一列算錯了：Q6 自己配的 KV cache 長度剛好 22 格，最後一步寫到最後一格時，sliding 層的 cache 會整個往前捲一格、把 <bos> 擠掉，所以熱圖的最後一列和正確的值差很多；其他列與生成的文字不受影響（第 7 章）。這一條是寫第 7 章前才發現的。
  • Q7 取 hidden state 的索引差一：SAE 是另外訓練好的一個小模型，專門把某一層 decoder block 輸出的向量（hidden state）拆成上萬個稀疏的 feature。這個 SAE 是在 block 20 的輸出上訓練的，程式餵給它的卻是 block 19 的輸出（第 8 章）。

完整清單（11 條程式問題、5 條投影片與程式不一致）以及各自分到哪一章，見全書大綱的對照表。

3　讀之前要準備什麼

3.1　預備知識

  • Python：函式、dict、list comprehension，看得懂 argparse。
  • PyTorch：tensor 的形狀與索引、torch.no_grad()、.to("cuda")。不需要訓練過模型，這份作業從頭到尾只做推論。
  • Transformer：聽過 self-attention、知道 LLM 一次預測下一個 token 就夠了。Gemma 2 的內部結構第 0 章會從頭畫一次。

3.2　要跑程式的話

只讀不跑也能讀完這本書：每一章都貼了真的執行輸出。想自己跑的話，需要一張 NVIDIA GPU，以及一個 Hugging Face 帳號：在帳號設定裡建立一個 read token，並在 Gemma-2-2b-it 的模型頁接受授權（兩件事的步驟見投影片 p.5–11；授權核准可能要等幾小時到幾天，核准後才能下載模型）。本機實測用的是一張 23.9 GiB 顯示記憶體的 GPU，模型以 fp16 載入後佔 4.87 GiB。

這個 repo 全部作業共用根目錄的一個 .venv，用 uv 管理（請先依 uv 官網安裝好它）。先 clone repo 並進入它的根目錄；之後所有指令都在 repo 根目錄執行，不要 cd 進 HW03/：

git clone https://github.com/lordleeber/ML2025-Spring-pytorch.git
cd ML2025-Spring-pytorch
uv sync
.venv/bin/hf auth login
.venv/bin/python HW03/hw3.py --seed 0
  1. 前兩行取得程式碼；uv sync 依照 pyproject.toml 與 uv.lock 建立 .venv。transformers 釘在助教指定的 4.47.0，sae-lens 釘在 5.x。
  2. hf auth login 貼上你的 read token，它會存進快取，之後不用再登入。也可以不登入，改在同一個 shell 先執行 export HF_TOKEN=hf_...（換成你的 token）再跑下一行。
  3. 最後一行一次跑完七題。第一次執行會先下載到 Hugging Face 快取：gemma-2-2b-it 約 5.3 GB，另外 Q1 的評分模型約 0.09 GB、Q7 的 SAE 約 0.3 GB。全部已在快取時，本機實測七題共 45.7 秒。終端機會用 ############ Q1 ############ 這樣的分隔線依序印出每一題的結果；HW03/outputs/ 會出現 9 張圖（Q2 三張、Q5 一張、Q6 一張、Q7 四張）。--seed 0 固定亂數，只影響有隨機取樣的 Q4；書中貼的實測輸出大多是用這一行跑出來的，不同的會在該處註明。

只想跑某一題就加 --q，例如 --q 3。每一題可以調的旗標，第 0 章會整理成一張表。

4　章節目錄

全書 14 頁：先用一篇補充章認識作業用的模型 Gemma-2-2b-it，第 0 章打底，接著一篇補充章講貫穿全書的 KV cache，第 1–9 章依作業題號推進，第 10 章總結，最後是附錄。每章的對應函式、行號與重點見全書大綱。章節還在撰寫中，寫好的章會在這裡加上連結。

  1. 補充章　認識 Gemma-2-2b-it：這份作業拆的是什麼模型

    Gemma 家族與發表時間、名字的每一段、知識蒸餾與 post-training、技術報告的架構描述對照本機 config；pt 與 it 並排實測：權重矩陣只改了約 7.6%，行為完全不同。

  2. 第 0 章　開工前：環境、CLI 與 Gemma-2-2b-it 模型總覽

    腳本的骨架、模型從哪裡載入、26 層 decoder 的形狀與 2,614,341,888 個參數怎麼算出來。

  3. 補充章　KV cache：生成時模型記住了什麼

    生成一個 token 為什麼不必重算前面；cache 存了什麼、佔多少記憶體、省多少時間；為什麼留在模型上的 cache 會改變 greedy 的答案。

  4. 第 1 章　Q1 Chat template：同一個問題，兩種 prompt

    套不套對話格式，回答與 coherence 分數差在哪裡；雙 <bos> 從哪裡來。

  5. 第 2 章　Q2 多輪對話：prompt 怎麼長大、下一個 token 怎麼選

    chat_history 如何串成一個越來越長的 prompt；三輪的 top-10 機率怎麼變。

  6. 第 3 章　Q3 Tokenization：一句話怎麼變成 token id

    SentencePiece 的 ▁ 記號、同一個字前面有沒有空白就是不同的 token。

  7. 第 4 章　Q4（上）取樣：top-k、top-p 與 generate 的隱藏預設值

    從 logits 到抽出一個 token；沒寫出來的 top_k=50 與 eos_token_id。

  8. 第 5 章　Q4（下）self-BLEU、seed 與可重現性

    怎麼用一個數字量「20 句有多像」；設了 seed 為什麼還不一定一樣。

  9. 第 6 章　Q5 句子表示與 t-SNE：同一個字，不同語境

    最後一層 hidden state 取平均當句子向量，Apple 的兩個意思為什麼分得開。

  10. 第 7 章　Q6 Attention map：逐步生成時誰在看誰

    KV cache、attention 矩陣的形狀，以及大量注意力流向 <bos> 的 attention sink。

  11. 第 8 章　Q7（上）Gemma Scope SAE 與 feature 10004

    稀疏自編碼器是什麼、JumpReLU 門檻；兩句話的最大 activation 該怎麼比。

  12. 第 9 章　Q7（下）逐 token、逐層的 activation

    「layer 24」到底是哪一層；把只在一層校正過的量尺拿去量別層。

  13. 第 10 章　總結與三級題庫

    全書串起來看 Gemma 2 的一次 forward；入門、進階、挑戰三級實作題。

  14. 附錄　名詞對照、速查表與延伸閱讀

    中英名詞對照、CLI 旗標與形狀速查、Problem 8–9 的三篇論文。
