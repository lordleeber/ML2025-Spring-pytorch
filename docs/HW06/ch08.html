第 8 章　Strong 提示與遺忘

第 7 章找到第一個清楚的遺忘：隨機抽 8 題範例訓練。這一章逐項實測投影片的 Strong 提示：多訓練幾個 epoch、weight decay、LoRA dropout、固定 few-shot 範例、self-instruct 資料，再加兩組本書自己的對照：只讓答案算 loss，以及把學習率調大到 1e-3，看看真正的遺忘長什麼樣。結果有兩個提示同時改善了數學和安全，有一個讓模型明顯遺忘，還有兩個在本書的設定下沒有作用。

8.1　怎麼比

規則和第 7 章相同：每個設定 3 個種子、greedy 評估、三個審查模型都判，主線看 Guard 8B，只對差距明顯大於種子與日期雜訊、三個審查模型方向一致的結果下結論。對照的基準也一樣：原模型 GSM8K 0.235、Safety（8B）0.838；預設的 1 epoch 是 0.371、0.889。這一章的實驗分散在 10 月 14 日到 16 日跑（weight decay、dropout、self-instruct 在 14 日，5 epochs 與固定 8-shot 在 15 日，只算答案與 lr 1e-3 在 16 日），每一組都帶著第 6 章說的日期雜訊。所有設定的三個種子並排：

8.2　多訓練幾個 epoch

投影片建議 3 到 5 個 epoch（--epochs）。5 個 epoch 是 9340 步，在本機訓練約 70 分鐘。結果是這一章最清楚的遺忘之一：Guard 8B 的安全率平均 0.772，三個種子全部低於原模型（0.838），比 1 epoch 低了 0.117；1B 和 ShieldGemma 方向相同。數學也沒有因為多看幾遍而進步：0.280，比 1 epoch 少 12 題，只比原模型多 6 題。

訓練的 loss 卻一路下降：1 epoch 平均 0.853，5 epochs 平均 0.461。loss 越低、測試越差，是典型的過擬合：模型越來越會背這 7,473 題的訓練資料（包括題目、範例與答案的每一個字），卻沒有越來越會算新題目；同時，越來越強的訓練訊號把它原本的回答習慣推得越來越遠。本書早期用 3 個 epoch 跑過一組（評估方式和這一章不同，只能看趨勢）：greedy 下 Accuracy 平均 0.303、Guard 8B 0.842，正好落在 1 epoch 與 5 epochs 之間。

這也說明了投影片為什麼把「epoch 3 到 5」列在 Strong 提示：它的前提是同時固定 few-shot 範例（範例程式在 epoch 設定旁的註解寫著：「If you use fixed few-shot examples, increase epoch」）。範例隨機時多訓練幾個 epoch，只會讓遺忘更嚴重。

8.3　weight decay 與 LoRA dropout

這兩個都是經典的正則化：weight decay 每一步把參數往 0 拉一點；dropout 訓練時隨機把一部分 LoRA 的輸入歸零，讓它不能依賴特定的路徑。用在 LoRA 上，weight decay 有一個特別的意義：LoRA 的參數往 0 拉，就是把模型往原模型拉。讀過 ML2022 HW14 的讀者會覺得眼熟：EWC 用 Fisher 資訊決定每個參數該被拉多緊，weight decay 則是對所有 LoRA 參數一視同仁地拉回原點。

實測的結果是：四個設定（weight decay 1e-2、1e-4，dropout 0.1、0.2）的數學與安全率，全部和預設的 1 epoch 在種子雜訊之內。這並不代表它們沒用，而是在 1 個 epoch、學習率線性降到 0 的設定下，預設本來就沒有遺忘，正則化沒有東西可以保護。要看出它們的效果，應該搭配會遺忘的設定（例如 5 epochs）一起試；本書沒有跑這個組合。

8.4　固定 few-shot 範例

這是 Strong 提示裡最值得注意的一項。投影片說，從訓練集隨機抽範例會讓模型過擬合，訓練與測試的範例不一致也會讓評估不穩，建議固定一組範例。hw6.py 的 --fixed-shots-seed 0 用固定的種子從訓練集抽出 8 題，訓練與評估的每一個 prompt 都用同一組、同樣的順序（第 1 章）。結果和第 7 章「隨機抽 8 題」形成強烈對比：

8-shotGSM8K publicSafety 8Btrain_loss

每題隨機抽 8 題0.2800.799（第 7 章）

同樣是 8 題範例、同樣的 loss 算法，固定之後，數學比原模型（同樣 8-shot prompt）多對 7 題，安全率則是本書所有設定裡最高的：三個種子 0.925、0.925、0.917，三個審查模型都判它比原模型安全。

train_loss 只有 0.089，是一個很重要的線索。每個訓練樣本都帶著同一組 8 題範例，而 loss 算整段文字（第 3 章）；這 8 題的每一個字，模型在前幾十步就背熟了，預測它們的 loss 趨近 0，把整體平均拉得很低。換個角度看，背熟之後，這些 token 幾乎不再產生梯度，模型真正在學的只剩最後那段答案。所以本書的推測是：固定範例之所以有效，一部分原因是它讓「整段算 loss」實際上變成了「只算答案」。下一節的實驗可以部分檢驗這個推測。

8.5　只算答案的 loss

第 3 章發現範例程式的 loss 算整段文字，8-shot 時答案只占 6.6% 的 token；第 7 章推測這是隨機 8-shot 會遺忘的原因。--completion-only-loss 改用 trl 的 DataCollatorForCompletionOnlyLM，只有最後一段答案算 loss。結果：

greedy，3 種子平均GSM8K publicSafety 8BSafety 1BSafety ShieldGemma
8-shot，整段算 loss（範例程式）0.2800.7990.6330.890
8-shot，只算答案0.3760.8440.6720.912
1-shot，整段算 loss（範例程式）0.3710.8890.7310.929
1-shot，只算答案0.3870.8560.6760.918

8-shot 的部分支持第 7 章的推測：只算答案之後，數學從 0.280 回到 0.376，比原模型在 8-shot prompt 下的 0.341 多對 5 題；安全率從 0.799 回到 0.844，和原模型的 0.838 相當，三個審查模型方向一致。隨機 8-shot 會遺忘，主因確實是範例的回答也被大量訓練。

1-shot 的結果則出乎意料：只算答案時，數學略好（0.387 對 0.371，在雜訊內），安全率卻比範例程式的預設低（8B 0.856 對 0.889，1B 0.676 對 0.731，三個審查模型方向一致），只比原模型略高。也就是說，第 5、7 章看到的「1 epoch 後更安全」，有一部分來自訓練了題目本身：預設的 loss 讓模型也學會預測 user 的那一段（「Q: … Let's think step by step. At the end, you MUST write the answer…」）。這為什麼會讓模型更常拒絕危險要求，本書沒有答案；它提醒我們，loss 算在哪些 token 上，影響的不只是要學的能力。

回到 8.4 節的推測：固定 8-shot（0.922）比只算答案的 8-shot（0.844）還要安全得多，所以「固定範例等於只算答案」只解釋了一部分。固定範例還讓評估時的 prompt 和訓練時完全一致，這可能是另一個原因。

8.6　self-instruct 資料

最後一項 Strong 提示是把訓練資料換成助教做的 self-instruct 版（--train-data self-instruct）。第 1 章看過，它的問題和最終答案都和原版相同，只是答案改成了原模型自己的寫法：幾乎沒有 <<…>> 計算標記、多一兩句說明、平均長一點。

結果是本書所有設定裡數學最好的：三個種子 0.485、0.455、0.492，平均 0.477，比預設多 14 題，也超過投影片 Strong 基準線的 0.455。安全率（8B 0.872）介於原模型與預設之間，三個審查模型都判它不比原模型差。

為什麼用模型自己的話訓練效果這麼好？一個解釋是：原版答案的計算標記與簡短寫法，對模型來說是一種陌生的格式，訓練有一大部分力氣花在學這個格式上；self-instruct 的答案就是模型本來的說話方式，訓練只需要把「算錯的地方」修正，不必改變它怎麼說話，原本的行為因此也比較不會被推走。這和 ML2022 HW14 的 replay 精神相通：replay 把舊任務的資料混進新任務一起訓練，讓模型在學新東西時不斷被提醒舊的行為；self-instruct 則是讓新資料本身就帶著舊的說話方式。本書沒有做實驗去拆解這兩個解釋的貢獻。

現在的做法：用模型自己的資料訓練

「用模型自己生成、再篩選過的資料來訓練它」在近年的語言模型後訓練裡很常見，例如用拒絕取樣（rejection sampling）從多個生成裡挑出正確的回答，再拿來微調。self-instruct 這份資料正是這種做法的縮影：取樣、用標準答案篩選、只留下對的。它的好處之一，就是訓練資料的分布和模型原本的輸出很接近，學新能力時對原本行為的擾動比較小。

8.7　對照：學習率 1e-3

為了讓讀者看到「真正的遺忘」長什麼樣，本書加了一組投影片沒有的對照：學習率調大 5 倍，到 1e-3，其餘照預設。結果是全書最嚴重的遺忘：Guard 8B 的安全率平均 0.632，比原模型低 0.206，三個種子分別是 0.600、0.633、0.662；1B 只剩 0.397，ShieldGemma 也掉到 0.810。數學 0.311，比預設少 8 題。

大學習率讓每一步更新都很大，LoRA 很快就把模型的行為推離原點。和 8.2 節的 5 epochs 對照：兩者都是「訓練訊號太強」，一個是步子太大，一個是走太多步，結果都是遺忘。投影片 Medium 提示要你「降低學習率」，從這組對照看得最清楚為什麼。

把本書的結果濃縮成一句話：會不會忘，取決於訓練訊號把模型推離原本的說話方式有多遠。學習率太大、訓練太久、或讓大量和任務無關的文字進入 loss，都會推得太遠；讓訓練資料貼近模型自己的寫法、讓訓練與評估的格式一致，則能在學到新能力的同時，把原本的行為留住。

重點回顧

  • 5 個 epoch：loss 降到 0.461，測試卻變差（Accuracy 0.280），Safety（8B）0.772 低於原模型：過擬合加上遺忘。
  • weight decay 與 LoRA dropout 在 1 epoch 時和預設沒有差別；預設本來就沒有遺忘，正則化沒有東西可保護。
  • 固定 8-shot 範例：數學 0.397、Safety 0.922，全書最安全；train_loss 0.089 顯示固定範例很快被背熟。
  • 只算答案的 loss：救回了隨機 8-shot 的遺忘（Safety 0.799 → 0.844）；但 1-shot 時安全率反而比預設低，代表訓練題目本身也影響安全行為。
  • self-instruct：數學最好（0.477），安全不比原模型差，精神上接近 replay。
  • lr 1e-3 的對照：Safety 0.632，全書最嚴重的遺忘。

自我測驗

1. 5 個 epoch 的 train_loss（0.461）比 1 個 epoch（0.853）低很多，為什麼測試的 Accuracy 反而比較差？

loss 量的是模型對訓練資料的預測有多準，包括題目、範例和答案的每一個字。多看幾遍之後，模型越來越會背這 7,473 題，loss 自然下降；但背熟訓練資料不等於會解新題目，這就是過擬合。同時，強烈的訓練訊號把模型的行為推離原本的樣子，連安全率也下降了。

2. 用在 LoRA 上的 weight decay，為什麼可以說是「把模型往原模型拉」？

LoRA 的輸出是原本的輸出加上 (α／r)·B A x。weight decay 把 A、B 往 0 拉，B A 越小，模型就越接近原模型；全部為 0 時就完全等於原模型。這和 EWC 拉住重要參數的精神類似，只是對所有 LoRA 參數一視同仁。

3. 固定 8-shot 的 train_loss 只有 0.089。這個數字能拿來和 1-shot 的 0.853 比較，說明固定 8-shot「訓練得比較好」嗎？

不能。loss 是整段文字的平均，固定 8-shot 的每個樣本都有同一組範例，這些 token 很快被背熟，loss 趨近 0，把平均拉低。兩個數字的組成完全不同，不能直接比較；要比較兩種設定，得看測試的 Accuracy 與 Safety。

4. 只算答案的 loss 救回了隨機 8-shot 的遺忘，卻讓 1-shot 的安全率比預設低。這兩個結果合起來告訴我們什麼？

loss 算在哪些 token 上，會影響的不只是要學的能力。8-shot 時，大量的範例回答進入 loss 是遺忘的主因，拿掉就好了；1-shot 時，題目本身（包括那句固定指令）進入 loss 反而讓模型更常拒絕危險要求。「整段算」和「只算答案」各有副作用，沒有一個在所有情況下都比較好。

5. 如果只能用一個 Strong 提示交作業，依本章的結果你會選哪一個？為什麼？

看目標而定。要數學最高，選 self-instruct（0.477，安全不比原模型差）；要同時兼顧數學與安全，選固定 few-shot 範例（0.397、0.922）。兩者都在三個種子、三個審查模型下一致地不比預設差，而增加 epoch 在範例隨機時反而會造成遺忘。
